# Deployment Guide — TuitionMeter

This guide takes you from a downloaded ZIP to a live Vercel URL.
No terminal required for GitHub. One terminal command needed for Firestore rules.

---

## Before you start — what you need

- A **GitHub account** (free) → github.com
- A **Firebase account** (free) → firebase.google.com  
- A **Vercel account** (free) → vercel.com

Sign up for all three with the same Google account if you want — it's easier.

---

## Part 1 — Upload the project to GitHub

### Step 1 — Create a new GitHub repository

1. Go to **github.com** and sign in
2. Click the **+** button in the top-right corner → **New repository**
3. Fill in:
   - **Repository name:** `tuition-meter` (or anything you like)
   - **Visibility:** Private _(recommended — keeps your code yours)_
   - **Do NOT** tick "Add a README file" — the project already has one
4. Click **Create repository**

GitHub will show you an empty repo page. Leave it open.

---

### Step 2 — Upload your files

> **Important:** You downloaded a ZIP file. You need to upload the **contents** of the zip, not the zip file itself.

1. Unzip the downloaded file on your computer. You'll get a folder called `tuition-meter`
2. Open that folder. You should see files like `package.json`, `README.md`, folders like `app/`, `lib/`, `components/`
3. Go back to your empty GitHub repo page
4. Click **uploading an existing file** (the link in the middle of the page)
5. **Drag the entire contents** of the `tuition-meter` folder into the upload area
   - Select all files and folders inside `tuition-meter` and drag them in
   - Do NOT drag in the `node_modules` folder — skip it if it's there
   - Do NOT drag in the `.next` folder — skip it if it's there
6. Scroll down, write a commit message like `Initial commit`
7. Click **Commit changes**

> **Note on the `node_modules` folder:** If your ZIP contains it, just don't upload it. It's auto-generated by `npm install` during Vercel's build — you don't need it in GitHub. It's 800MB+ and would take forever to upload anyway.

GitHub will process the upload. It may take 30–60 seconds. When it's done, you'll see all your files listed.

---

## Part 2 — Set up Firebase

### Step 3 — Create a Firebase project

1. Go to **console.firebase.google.com**
2. Click **Add project**
3. Name it `tuition-meter` (or anything)
4. Disable Google Analytics (not needed) → click **Create project**
5. Wait for it to finish → click **Continue**

---

### Step 4 — Create a Firestore database

1. In the left sidebar, click **Build** → **Firestore Database**
2. Click **Create database**
3. Choose **Start in production mode** → click **Next**
4. Choose a location — pick `asia-south1 (Mumbai)` for Bangladesh users → click **Enable**

Wait for Firestore to provision. This takes about 30 seconds.

---

### Step 5 — Deploy Firestore security rules

This is the one step that needs a command. You have two options:

**Option A — Use the Firebase console (no terminal needed):**

1. In Firestore, click the **Rules** tab
2. Delete everything in the editor
3. Open the file `firestore.rules` from your unzipped project folder (open it in Notepad or any text editor)
4. Copy all the text from that file
5. Paste it into the Firebase rules editor
6. Click **Publish**

**Option B — Use Firebase CLI (terminal):**
```bash
npm install -g firebase-tools
firebase login
firebase use --add   # pick your project
firebase deploy --only firestore
```

> **Why rules matter:** Without proper rules, anyone could read or delete data. The rules file enforces that only admins can do destructive actions.

---

### Step 6 — Deploy Firestore indexes

Indexes are needed for the benchmark filter queries (combining `status` + `created_at` + `area` etc.).

**Option A — Firebase console:**

1. In Firestore, click the **Indexes** tab → **Composite** tab
2. You need to manually create the indexes listed in `firestore.indexes.json`
3. The most important ones are:
   - Collection: `tuition_records` | Fields: `status ASC`, `created_at ASC`
   - Collection: `tuition_records` | Fields: `status ASC`, `created_at ASC`, `area ASC`
   - Collection: `tuition_records` | Fields: `status ASC`, `created_at ASC`, `university ASC`

> **Shortcut:** When a query needs an index that doesn't exist yet, Firebase throws an error in the browser console with a direct link to create that exact index. You can just run the app and create indexes on demand the first time each filter combination is used.

**Option B — Firebase CLI:**
```bash
firebase deploy --only firestore:indexes
```

---

### Step 7 — Enable Authentication

1. In the left sidebar, click **Build** → **Authentication**
2. Click **Get started**
3. Click **Email/Password** under Native providers
4. Toggle **Enable** → click **Save**

Now create your admin account:

1. Click the **Users** tab
2. Click **Add user**
3. Enter your admin email and a strong password
4. Click **Add user**

> Write down this email and password — you'll use them to log in at `/admin`.

---

### Step 8 — Get your Firebase config values

1. Click the ⚙️ gear icon → **Project settings**
2. Scroll down to **Your apps** section
3. If no app is listed, click the `</>` (web) icon to add a web app
   - Give it a nickname: `tuition-meter-web`
   - Do NOT tick "Firebase Hosting"
   - Click **Register app**
4. You'll see a config block that looks like this:

```javascript
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "your-project.firebaseapp.com",
  projectId: "your-project-id",
  storageBucket: "your-project.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abc123"
};
```

5. Copy each of these values — you'll need them in the next step

---

## Part 3 — Deploy to Vercel

### Step 9 — Connect Vercel to your GitHub repo

1. Go to **vercel.com** and sign in (or sign up — use the "Continue with GitHub" button)
2. Click **Add New** → **Project**
3. You'll see your GitHub repos listed. Find `tuition-meter` and click **Import**
4. Vercel auto-detects it as a Next.js project. Leave all settings as default.
5. **Do NOT click Deploy yet** — you need to add environment variables first.

---

### Step 10 — Add environment variables in Vercel

Still on the import/configure screen:

1. Scroll down to the **Environment Variables** section
2. Add each variable one by one:

| Variable Name | Value (from Step 8) |
|---|---|
| `NEXT_PUBLIC_FIREBASE_API_KEY` | your `apiKey` value |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | your `authDomain` value |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | your `projectId` value |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | your `storageBucket` value |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | your `messagingSenderId` value |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | your `appId` value |

3. After adding all 6 variables, click **Deploy**

Vercel will now build and deploy the project. This takes 1–2 minutes.

---

### Step 11 — You're live

When the build finishes, Vercel gives you a URL like:
`https://tuition-meter-yourname.vercel.app`

That's your live site. Click it to confirm everything loads.

## Part 5 — Future updates (editing files on GitHub web)

Yes — you can edit any file directly on GitHub's website without any software:

1. Go to your repo on github.com
2. Click on any file (e.g. `lib/data.ts` to add more areas)
3. Click the **pencil icon** (Edit this file) in the top-right of the file view
4. Make your changes
5. Scroll down → **Commit changes** → write a message → **Commit directly to main**

Vercel automatically detects every commit to your `main` branch and **redeploys automatically**. So every GitHub save = a new live version within ~1 minute.

## Adding more data (no code needed)

### To add more areas, subjects, universities, departments:

Open the file `lib/data.ts` on GitHub web, find the relevant array, and add entries. Example — adding a new area:

```typescript
// Find the AREAS array and add your entry
export const AREAS: string[] = [
  // ... existing areas ...
  'Tongi',          // ← just add it here
  'Ashulia',        // ← and here
];
```

Commit the change → Vercel redeploys → the new options appear in the form dropdown.

## Common issues

**"No data" on benchmark page after submitting**

Firestore may need 30–60 seconds to index the new record. Also check: is the record status `approved`? By default new submissions auto-approve (see `lib/benchmark.ts` — the `status: 'approved'` line).

**Firebase: Error (auth/invalid-api-key)**

One of your environment variables in Vercel is wrong. Go to Vercel → your project → Settings → Environment Variables and double-check each one against your Firebase config.

**Benchmark shows Low Confidence on everything**

That's expected with a new database — you need 10+ matching records for Medium Confidence, 50+ for High. It'll improve as the platform gets real submissions.

**Filters not working / Firestore index errors**

Open browser DevTools (F12) → Console tab. Firebase will print an error with a link that says "You can create it here: [link]". Click that link, it opens Firebase console with the index pre-filled. Click Create. Wait 2–5 minutes for it to build.

**Admin page redirects or shows blank**

Make sure Firebase Authentication is enabled (Step 7) and your admin user exists. The `/admin` route requires a valid Firebase Auth session.
